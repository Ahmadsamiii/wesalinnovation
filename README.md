# وصال

منصة ذكاء اصطناعي عربية تساعد الأشخاص ذوي الإعاقة في السعودية على الوصول إلى معلومات
موثوقة عن حقوقهم والخدمات والتقنيات المساعدة المتاحة لهم.

---

## البنية

| الطبقة | الوصف |
|---|---|
| الواجهة | `index.html` — تطبيق صفحة واحدة، بلا خطوة بناء وبلا اعتماديات. الأنماط والسكربت مضمّنان في الملف نفسه. |
| الخلفية | `api/` — نقاط PHP تتكلّم JSON وتتشارك `db.php`. |
| قاعدة البيانات | MySQL 5.7+ عبر PDO — كل الجداول معرّفة في `schema.sql`. |
| النموذج | Gemini أساسي (قابل للتبديل مع OpenAI/Claude/Kimi عبر `AI_PROVIDER`)، برد متدفق كلمة كلمة (SSE) عبر `chat-stream.php` وبديل تلقائي بينها، وقاعدة معرفة محلية داخل الواجهة كملاذ أخير. |
| الصوت | أصوات سعودية عبر `voice.php` (Groq ثم Azure)، وأصوات المتصفح بديلاً تلقائياً. انظر «الصوت السعودي» أدناه. |

لا يوجد `npm` ولا `composer` ولا خطوة تجميع: ما في المستودع هو ما يُرفع للخادم.
الاستثناء الوحيد `workspace/`: نظام إدارة المشاريع الداخلي، تطبيق Laravel مستقل
بقاعدة بياناته، له خطوات تثبيت خاصة في `workspace/README.md`. يعمل على `/workspace/`
داخل الموقع نفسه (أو على نطاقه الفرعي قبل التبديل)، ويشارك المنصة الحساب والدور والجلسة
(انظر «الدخول الموحد» أدناه). لا يرفعه `deploy.sh` إلى الموقع العام؛ ينشره سكربته
`workspace/deploy.sh`، ويستدعيه `deploy.sh` بعد نجاح نشر الموقع متى جُهّز الخادم له
(`workspace/DEPLOY.md`).

## التشغيل

### المتطلبات

- PHP **8.0** فأحدث، مع `pdo_mysql` و `curl` و `mbstring`
- MySQL 5.7 فأحدث (أو MariaDB 10.3+)
- Apache مع `mod_rewrite` و `mod_headers` — أو خادم مكافئ

### الخطوات

**١. أنشئ قاعدة البيانات وحمّل المخطط**

```bash
mysql -u USER -p -e "CREATE DATABASE wesal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u USER -p wesal < schema.sql
```

**٢. اضبط الإعدادات**

```bash
cp api/config.example.php api/config.php
```

ثم افتح `api/config.php` واملأ بيانات قاعدة البيانات ومفتاح Gemini على الأقل.
كل ثابت موثّق داخل الملف.

**٣. ارفع الملفات إلى جذر الموقع**

ارفع محتويات المستودع إلى `public_html` (أو ما يعادله). تأكّد أن `.htaccess`
وصل فعلاً — بعض عملاء FTP يخفون الملفات التي تبدأ بنقطة.

**٤. أنشئ حساب المشرف**

افتح الموقع وسجّل حساباً جديداً. **الحساب الأول في قاعدة بيانات فارغة يصبح
مشرفاً عاماً تلقائياً** — سجّله بنفسك قبل فتح الموقع للناس.

**٥. تحقّق**

افتح `‎/api/diag.php` وأنت مسجّل بحساب المشرف. تعرض الصفحة حالة الاتصال
بقاعدة البيانات، وحالة مفتاح النموذج، وسلامة ملفات الشعار.

> بعد التأكد من التشغيل، احذف `api/diag.php` من الخادم أو قيّده بعنوان IP —
> فهو يكشف جزءاً من مفتاح النموذج ورد المزوّد الخام لمن يملك حساب مشرف.

## ملاحظات تشغيلية

### الإعدادات المتزامنة بين الطرفين

ثلاث قيم معرّفة في مكانين ويجب أن تتطابق، وإلا اختلف ما يراه المستخدم عمّا
يطبّقه الخادم:

| القيمة | في `api/config.php` | في `index.html` |
|---|---|---|
| حصة الزائر | `GUEST_LIMIT` | `GUEST_LIMIT` |
| رصيد المستخدم | `USER_TOKENS` | `USER_TOKENS` |
| دورة التجديد | `RENEW_HOURS` (ساعات) | `RENEW_MS` (ميلي ثانية) |

### حدود الاستخدام

الحدود مخزّنة في جدول `rate_limits` ومفتاحها عنوان IP — لا الجلسة — حتى لا
يمنح حذف الكوكي حصةً جديدة. ثلاث طبقات:

- **لكل دقيقة لكل IP** — تُضبط في الكود عند كل نداء `rateLimit()`
- **`CHAT_DAILY_IP_LIMIT`** — سقف يومي لنقاط الأسئلة من عنوان واحد
- **`CHAT_DAILY_TOTAL_LIMIT`** — سقف يومي للمنصة كلها، وهو قاطع الدائرة الذي
  يحمي فاتورة المزوّد. اضبطه على رقم يناسب ميزانيتك قبل أي إطلاق واسع.

الصفوف القديمة تُنظَّف تلقائياً بعد يومين.

### خلف Cloudflare

اضبط `TRUST_PROXY` على `true` فقط إذا كان الموقع خلف وكيل عكسي فعلاً. بدون
وكيل، تفعيله يسمح لأي زائر بانتحال عنوانه عبر ترويسة `X-Forwarded-For`
وتجاوز كل الحدود أعلاه.

### ترقية قاعدة بيانات قائمة

`ensureSchema()` في `api/db.php` تضيف الأعمدة والجداول الناقصة تلقائياً عند
أول طلب، لتبقى القواعد القديمة متوافقة. أي تعديل على البنية يجب أن يُضاف في
`schema.sql` **و** في `ensureSchema()` معاً.

### الصوت السعودي

القراءة الصوتية والأسئلة بالصوت تعمل بلا أي إعداد بأصوات المتصفح. وبمفتاح واحد
على الأقل في `config.php` تقرأ الواجهة بأصوات سعودية عبر `api/voice.php`، بطبقات
مجانية تتجدد حصة كل منها:

| الطبقة | الأصوات | الحصة المجانية | ملاحظات |
|---|---|---|---|
| Groq `canopylabs/orpheus-arabic-saudi` | عبدالله، فهد، سلطان، لولوة، نورة، عائشة | يومية وصغيرة | نسخة معاينة، و200 حرف للطلب |
| Azure Speech `ar-SA` | حامد، زارية | شهرية (الفئة F0) | 20 طلباً في الدقيقة |
| صوت المتصفح | ما في جهاز المستخدم | بلا حد | البديل الأخير دائماً |

- **التفعيل:** ضع `GROQ_KEY` أو `AZURE_SPEECH_KEY` (مع `AZURE_SPEECH_REGION`) أو
  كليهما في `config.php`، ثم افتح `api/diag.php` بحساب المشرف: يقرأ كلمة واحدة من
  كل طبقة فعلاً ويعرض النتيجة. إن رفض Groq النموذج فاقبل شروطه من لوحته أولاً.
- **ثبات الصوت:** الرد الواحد يُقرأ كله بطبقة جملته الأولى. وحين تنفد حصة طبقة
  يُسجَّل ذلك في `STORAGE_DIR/voice/state.json`، فتبدأ الردود التالية من الطبقة
  بعدها حتى موعد تجدد الحصة.
- **الحماية:** حد في الدقيقة لكل IP، و`VOICE_DAILY_IP_CHARS` حرفاً يولّدها المزوّد
  لكل IP في اليوم، و`VOICE_DAILY_IP_STT` تسجيلاً. والطلب من موقع آخر يُرفض.
  الفئتان المجانيتان لا تحاسبان على التجاوز: المزوّد يرفض الطلب فقط.
- **الحفظ المؤقت:** كل صوت مولَّد يُحفظ في `STORAGE_DIR/voice/cache` ببصمة النص
  والصوت، فالعبارات المتكررة لا تستهلك الحصة مرتين. سقفه `VOICE_CACHE_MB`
  ويُحذف الأقدم استخداماً أولاً.
- **الإملاء:** المتصفح يحوّل الكلام إلى نص بنفسه حيث يستطيع. وفي غيره (Firefox
  مثلاً) يُسجَّل السؤال ويُفرَّغ عبر Groq Whisper بالمفتاح نفسه، ولا يُحفظ
  التسجيل. النص يظهر في خانة الرسالة ليراجعه صاحبه قبل الإرسال، والسؤال المرسل
  بالصوت يُقرأ رده بالصوت دون تفعيل القراءة التلقائية.
- **الجلسة:** طلبات الصوت تمر أثناء البث لأن `chat-stream.php` يحرر قفل الجلسة
  (انظر «دورة السؤال في المحادثة»)، و`voice.php` يحرره أيضاً فتُجهَّز الجملة
  التالية أثناء قراءة الحالية.
- **الخصوصية:** قسم «القراءة الصوتية والأسئلة بالصوت» في سياسة الخصوصية يصف هذا
  السلوك، وأي مزوّد جديد أو تغيير فيما يُرسل إليه يستلزم تحديثه.
- **الفحص:** `php tools/check-voice.php` دون شبكة ولا قاعدة بيانات.

## الأدوار ورحلة كل دور

للحساب دور واحد، والأدوار اثنا عشر هي نفسها في المنصة ومساحة العمل. الثلاثة الأولى
للمحادثة، والتسعة الباقية لمساحة العمل (مصدرها `workspace/config/roles.php`، ويفحص
`tools/check-roles.php` أن أسماءها ومفاتيحها لا تختلف بين النظامين).

| الدور | يرى | يقدر |
|---|---|---|
| **مدير النظام** `admin` (`sysadmin` في مساحة العمل) | كل شيء | كل ما تحت، إضافةً إلى: تحرير محتوى صفحة الهبوط وحسابات التواصل، تغيير أي دور، إيقاف الحسابات وحذفها، إعادة تعيين كلمات المرور، منح الرصيد، سجل العمليات |
| **مشرف** `mod` | المستخدمين، الرسائل، التذاكر | عرض المستخدمين، الرد على الرسائل وتعليمها مقروءة، إغلاق التذاكر، دعوة مستفيدين |
| **مراجع محتوى** `reviewer` | التذاكر | متابعة بلاغات دقة المعلومات وإغلاقها |
| **مستفيد** `user` | حسابه فقط | المحادثة، ملفه الشخصي، محادثاته المحفوظة، طلبات الدعم، تصدير بياناته أو حذف حسابه |
| **المدير التنفيذي** `executive`، **مدير المشاريع** `pm`، **المدير المالي** `finance`، **المدير الطبي** `medical`، **عضو الفريق** `team_member`، **العميل** `client` | مساحة العمل بصلاحيات دوره | ما يحدده دوره في مساحة العمل. في المحادثة يبقى مستفيداً عادياً |
| **مدير الموارد البشرية** `hr` | مساحة العمل، وقائمة الموظفين في المنصة | بيانات الموظفين (المسمى والقسم وتاريخ الالتحاق)، ومتابعة طلبات التوظيف وإغلاقها (الاعتماد للمدير التنفيذي)، ودعوة الموظفين |
| **مدير علاقات العملاء** `crm` | مساحة العمل، وقائمة العملاء في المنصة | دعوة العملاء ومتابعتهم |

### من يدعو من

الداعي يكتب اسم المدعو الكامل بالعربية (ثلاثة أسماء على الأقل) وجواله وبريده ودوره، والمدعو يكمل
اسمه بالإنجليزية وتاريخ ميلاده وكلمة المرور. الخادم هو الذي يفرض المصفوفة (لا الواجهة):

| الداعي | يدعو |
|---|---|
| مدير النظام | أي دور من الاثني عشر |
| مدير الموارد البشرية | الموظفين دون المناصب العليا: عضو الفريق، مدير المشاريع، المدير المالي، المدير الطبي، مدير علاقات العملاء، المشرف، مراجع المحتوى. لا المدير التنفيذي ولا مدير النظام ولا مدير الموارد البشرية |
| مدير علاقات العملاء | العميل وحده |
| المشرف | المستفيد وحده، كما كان |
| غيرهم | لا أحد |

**صلاحية الدعوة** `INVITE_TTL_DAYS` يوماً (15 افتراضياً) من آخر إرسال، ثم يرفضها الخادم برسالة
«انتهت صلاحية هذه الدعوة». جدول الدعوات يعرض لكل دعوة حالتها (بانتظار القبول، مقبولة، منتهية)
وتاريخ الإرسال و«صالحة حتى» و«المتبقي». إعادة الإرسال تعطي رابطاً جديداً بصلاحية كاملة
وتوقف السابق، والحذف يوقف الرابط فوراً. يديرها من يحق له الدعوة بدورها، والموارد البشرية
وعلاقات العملاء دعواتهم وحدها. الدعوة المقبولة سجلّ لحساب قائم فلا تُعاد ولا تُحذف. في
التسجيل برابط الدعوة يظهر الاسم والجوال والبريد مقفلة كما كتبها الداعي.

يخزّن الحساب في قاعدة المنصة عمودين: `role` (مستفيد أو مراجع أو مشرف أو مدير نظام)
و`org_role` (أدوار مساحة العمل). الدور الفعلي: مدير النظام إن كان `role` هو `admin`،
وإلا `org_role` إن وُجد، وإلا `role`. لا دور مخزّن مرتين، ولا يفقد أي دور عند التحويل.

**أول حساب يُسجَّل في قاعدة بيانات فارغة يصبح مدير النظام تلقائياً.** بعد ذلك
تُسنَد الأدوار من لوحة مدير النظام أو عبر دعوة بالبريد.

### حواجز تمنع إقفال المنصة على نفسها

- لا أحد يغيّر دوره أو يوقف حسابه أو يحذفه بنفسه
- لا يمكن تنزيل آخر مدير نظام نشط أو إيقافه أو حذفه
- حذف الحساب الذاتي يتطلب كلمة المرور، ويُرفض لآخر مدير نظام

### الدخول الموحد ومساحة العمل

حساب واحد وشاشة دخول واحدة (`/login`) وجلسة واحدة للمحادثة ولمساحة العمل. الجلسة صف في
جدول `auth_sessions`، وكوكي `wesal_auth` على النطاق الأعلى (`.wesalinnovation.sa`، ويُشتق
من `SITE_URL`). الصف هو المرجع الوحيد لمهلتي الخمول والحد الأقصى، فالخروج أو الإيقاف أو
الخمول في أحد النظامين يُنهي الآخر. أصحاب الأدوار (غير المستفيد) مهلتهم 15 دقيقة خمولاً
و12 ساعة حداً أقصى، والمستفيد 30 دقيقة و24 ساعة.

- **مطفأ افتراضياً** في الطرفين: `UNIFIED_SESSION` في `api/config.php` و`UNIFIED_AUTH` في
  `.env` مساحة العمل. بإطفائهما يبقى كل شيء كما كان تماماً، وهو الرجوع الفوري.
- **ترتيب التشغيل:** المنصة أولاً ثم مساحة العمل. عكسه يحوّل الجميع إلى شاشة لا تضع الكوكي.
- **الحسابات القديمة في مساحة العمل** تُربط بأداة `php artisan platform:link-accounts`:
  تقرير جاف، ثم تنفيذ على الخطة نفسها بعد نسخة `mysqldump`، مع تراجع بالدفعة. عند تعارض
  كلمة المرور تبقى كلمة مرور المنصة. الخطوات الكاملة في `workspace/DEPLOY.md`.
- **الوجهة بعد الدخول:** المستفيد إلى `/chat`، وصاحب الدور إلى `/workspace/`، ومدير النظام
  يختار. من دخل بكلمة مرور مؤقتة يذهب إلى المحادثة ليغيّرها. الرابط `?next=` لا يُقبل إلا
  على الموقع ونطاقاته الفرعية.
- **إدارة الحسابات والأدوار في مكان واحد:** تبويب «المستخدمون والأدوار» في لوحة المنصة.

```bash
php tools/check-roles.php          # الأدوار تطابق مساحة العمل، ومصفوفة الدعوات
php tools/check-invites.php        # الدعوات على الخادم (تحتاج قاعدة تجريبية محلية)
php tools/check-auth-session.php   # الجلسة الموحدة وعقد الكوكي (قاعدة تجريبية)
```

### تحرير محتوى صفحة الهبوط

من تبويب **محتوى صفحة الهبوط** في لوحة مدير النظام: كل نصوص الصفحة الرئيسية
وشريط التنقل والتذييل، بالعربي والإنجليزي، مع معاينة حيّة لشاشة الحاسوب
والجوال بجانب المحرر.

- **مسودة ثم نشر:** كل تعديل يُحفظ تلقائياً في مسودة مشتركة بين مديري النظام،
  ولا يراه الزوار حتى «نشر». «تجاهل المسودة» يرجع للمنشور. لو حفظ مدير آخر
  قسماً مختلفاً في نفس الوقت يُدمج عمله، ولو تغيّرت المسودة قبل لحظة النشر
  يُرفض النشر حتى تراجعها.
- **البطاقات** (المزايا، الخطوات، المصادر، حماية البيانات، مؤشرات الثقة،
  أمثلة حقل السؤال): إضافة وحذف وإخفاء وترتيب بالسحب أو بالأزرار، وأيقونة لكل بطاقة.
- **الإرجاع للأصل** على ثلاثة مستويات: حقل، قسم، الصفحة كلها — والأخيران
  بخيار «العربي فقط» أو «الإنجليزي فقط» أو «كل شيء».
- **المعاينة** هي الصفحة نفسها بوضع `?lp-preview=1` داخل iframe على نفس
  النطاق، وتتلقى المسودة عبر `postMessage`. النقر على أي نص فيها يفتح حقله
  في المحرر. لهذا `X-Frame-Options` في `.htaccess` هي `SAMEORIGIN` لا `DENY`.

**البنية:** السجل في `api/landing-schema.php` هو المرجع الوحيد للحقول
وأنواعها وحدودها ونصوصها الافتراضية. الخادم يخزّن في `landing_content` صفين
فقط (`live` و`draft`)، كل منهما «الفروقات عن الافتراضي»، فالحقل الذي لم
يُعدَّل يتبع السجل تلقائياً. الواجهة تتعامل مع المستند الكامل، والتحويل
والتحقق في `api/content.php` وحده. محتوى النظام السابق (`site_content`)
يُرحَّل تلقائياً عند أول طلب.

- الروابط تقبل `https` فقط، والنصوص تُعرض كنص خالص (`textContent`) لا HTML
- بطاقة مضافة بلا ترجمة إنجليزية تظهر بنصها العربي للزائر الإنجليزي
- **لإضافة حقل:** سطر في `landingSchema()` + `data-lp="القسم.الحقل"` على
  العنصر في `index.html` بنفس النص العربي (`data-lp-ph` لنص الحقل،
  `data-lp-href` للرابط). **لإضافة قائمة:** حاوية `data-lp-list` فيها
  `<template>` للبطاقة. بعدها شغّل `php tools/check-landing.php` ويجب أن ينجح.
- عند تعديل `assets/landing-editor.*` ارفع `LPE_VER` في `index.html` حتى لا
  يُقدَّم الملف القديم من ذاكرة المتصفح.

### شعارات الجهات في «مصادر البيانات»

كل بطاقة في القسم تعرض شعار جهتها في لوحة ثابتة المقاس، والشعار **يتبع نطاق
البطاقة**: `srcLogo()` في `index.html` تبحث عن النطاق (بلا `www.` ولا مسار) في
`SRC_LOGOS`، فبطاقة يضيفها المدير بنطاق معروف يظهر شعارها وحدها، وبطاقة بنطاق
بلا ملف تظهر برمز عام بنفس المقاس. في المعاينة، النقر على الشعار يفتح حقل النطاق.

- الملف `assets/sources/<النطاق>.webp`، لوحة شفافة 800×320 (أربعة أضعاف مساحة
  العرض)، والشعار فيها محجَّم بمساحته لا بعرضه حتى تتوازن الشعارات العريضة
  والمربعة. لا تضع الملف يدوياً، جهّزه بالأداة:
  ```bash
  php tools/source-logo.php ~/Downloads/apd.png apd.gov.sa
  ```
  تقبل PNG وJPEG وWebP (الخلفية البيضاء تصير شفافة)، و`--tint=#RRGGBB` لشعار لا
  تتوفر منه إلا نسخة بيضاء، و`--scale` لتعديل بصري بسيط. ملف SVG: صدّره PNG أولاً.
- أضف النطاق إلى `SRC_LOGOS` برقم `1`، وعند **استبدال** ملف موجود ارفع رقمه حتى
  لا تبقى النسخة القديمة في ذاكرة المتصفحات (الصور تُخزَّن 30 يوماً).
- إن كانت البطاقة من البطاقات الافتراضية فحدّث مكان الشعار في بطاقتها الثابتة
  بالصيغة نفسها، ثم شغّل `php tools/check-landing.php`: يفشل إن نقص ملف أو زاد،
  أو اختلف مقاسه، أو عرضت بطاقة ثابتة غير شعار نطاقها.
- الشعار زخرفي (`alt=""`) لأن اسم الجهة مكتوب تحته، وفي الوضع الداكن يظهر أبيض.
- **البطاقة رابط لموقع جهتها:** `https://` ونطاقها كما يظهر فيها (`srcHref()` من
  `data-lph`)، ويفتح في نافذة جديدة يعلنها قارئ الشاشة بعد اسم الجهة
  (`newTabHint()`، كبطاقات مصدر الإجابة). الرابط على الاسم وطبقته تغطي البطاقة،
  فالنقر في أي مكان منها يفتحه، وفي المعاينة يفتح حقل ما تحته كالعادة. موقع لا يفتح
  إلا بـ`www.` أو بمسار: اكتبه كذلك في حقل النطاق، والشعار يبقى كما هو.
  و`php tools/check-landing.php` يفشل إن اختلف رابط بطاقة ثابتة عن نطاقها.
- شعارات الجهات السبع في القائمة الافتراضية من ملفاتها الرسمية الملوّنة، ومثلها
  شعارا هيئة حقوق الإنسان وبنك التنمية الاجتماعية. هاتان من قاعدة المعرفة وليستا
  في القائمة، فيظهر شعاراهما تحت إجابات المحادثة، وفي القسم إن أضافهما المدير.
  الرمز العام يظهر اليوم لنطاق لا ملف له فقط.
- الأسماء والشعارات نفسها تظهر تحت إجابات المحادثة (القسم التالي).

### مصدر الإجابة في المحادثة

تحت كل إجابة مبنية على صفحات رسمية بطاقة لكل جهة، ثلاث على الأكثر: شعارها
واسمها ونطاقها، وتفتح الصفحة نفسها التي أُخذت منها المعلومة. الإجابة التي لم
تُبنَ على مصدر رسمي لا يظهر تحتها شيء.

- **من أين تأتي الجهة:** الاسترجاع (`ragRetrieve()` في `api/rag.php`) يجلب حتى
  أربعة مقاطع لكل سؤال، وتدخل توجيه النموذج مرقّمة (`ragContextBlock()`). النموذج
  يكتب بعد إجابته سطراً مخفياً `===SRC===` بأرقام ما استخدمه فعلاً، قبل ذيل
  الأسئلة `===ASK3===`. الخادم يقبل الأرقام التي جلبها هو فقط (`chatSources()` في
  `api/chat-shared.php`)، فلا تظهر جهة لم نأخذ منها شيئاً مهما كتب النموذج، ثم
  يرسلها حدث `sources` في البث أو حقل `sources` في `chat.php`.
- **اسم الجهة وشعارها بالنطاق:** من قائمة «مصادر البيانات» المنشورة، فالجهة
  التي يضيفها المدير هناك تظهر تحت الإجابات باسمها، والنطاق الفرعي يأخذ جهة
  نطاقه. جهة من قاعدة المعرفة ليست في القائمة تأخذ اسمها من `SRC_NAMES` في
  `index.html` إن وُجد، وإلا من عنوان صفحتها. وشعارها من `SRC_LOGOS` كأي نطاق،
  وإلا فرمز عام.
- **قاعدة المعرفة (`kb_chunks`):** يعبّئها `tools/rag/ingest-kb.php` من ملفات JSON
  بصيغة `{url, title, text, ok}`، ومعها `ref` اختياري: المرجع الرسمي الذي يُنسب
  إليه النص إن كان غير `url`. أمر `content:export-kb` في مساحة العمل يصدّر
  المحتوى الصحي المعتمد بـ`ref` من «المرجع الرسمي»، فتظهر وزارة الصحة مثلاً لا
  مساحة العمل. `url` يبقى هوية الصفحة، وإعادة التلقيم تستبدل مقاطعها.
- **النسخ والبلاغ عن خطأ** يضمّان المصادر وروابطها، فيعرف المراجع أي صفحة يراجع.
- **تشخيص المحادثة** في نظرة عامة لوحة مدير النظام (وفي `api/diag.php`): عدد
  صفحات قاعدة المعرفة وجهاتها، وصحة الرد المباشر آخر سبعة أيام. حين يتعطل البث
  في المتصفح قبل أول كلمة يُسأل `chat.php` بدله، ويُسجَّل السبب ومدة الانتظار في
  `chat_logs` (`fallback` و`fallback_ms`).

```bash
php tools/check-sources.php   # فصل ذيل الرد، والجهات مما جُلب فقط
```

### إعادة تعيين كلمة المرور

ثلاثة مسارات:

1. **المستخدم بنفسه** — «نسيت كلمة المرور؟» في صفحة الدخول، فيصله رابط بالبريد
2. **مدير النظام يرسل رابطاً** لبريد المستخدم؛ ولو تعذّر إرسال البريد من
   الخادم يُعرض الرابط لينسخه ويسلّمه بنفسه
3. **مدير النظام يولّد كلمة مرور مؤقتة** يسلّمها بقناة موثوقة، ويُطالَب
   المستخدم بتغييرها عند أول دخول

الرموز تُخزَّن كهاش `sha256` لا كنص، وتُستخدم مرة واحدة، وتنتهي خلال ساعتين.
نموذج «نسيت كلمة المرور» يعطي الرد نفسه سواء وُجد البريد أو لا، حتى لا يُستخدم
لمعرفة من هو مسجّل في المنصة.

## الحسابات التجريبية

لتجربة كل دور بنفسك دون المساس بحسابات حقيقية: من لوحة مدير النظام ← تبويب
**المستخدمون** ← قسم «الحسابات التجريبية»، أو من الطرفية:

```bash
php tools/seed-demo.php           # إنشاء/تجديد الحسابات الأربعة
php tools/seed-demo.php status    # كم حساباً موجود الآن
php tools/seed-demo.php purge     # حذفها كلها
```

أربعة حسابات حقيقية في قاعدة البيانات — مدير نظام، مشرف، مراجع محتوى،
مستفيد — بكلمات مرور **تُولَّد عشوائياً وتُعرض مرة واحدة** عند الإنشاء، ومعها
رسائل تواصل وتذاكر دعم كأمثلة حتى لا تكون لوحات المشرف والمراجع فارغة.

هذا يعاكس الطريقة القديمة عمداً: كانت حسابات تجريبية تُزرع في متصفح كل زائر
تلقائياً بكلمة مرور مكتوبة في الكود، وتُقبل محلياً عند تعذّر الوصول للخادم —
أي باب خلفي لواجهة المشرف. الحسابات الحالية على الخادم فقط، ولا تُنشأ إلا
بطلب صريح من مدير نظام، وتُحذف كلها بأمان عبر علامة `is_demo` — لا يُمكن أن
يُحذف حساب حقيقي بالخطأ معها.

**حاجزان يمنعان إقفال المنصة على نفسها:** لا يمكن الزرع في منصة بلا مدير
نظام حقيقي (لأن حساب العرض سيصبح المدير الوحيد)، ولا يمكن الحذف الجماعي إن
كان سيُفرغ المنصة من مديريها النشطين.

## الاستبيانات

منشئ استبيانات كامل — استبيانات غير محدودة، يتحكم مدير النظام والمشرف
بأسئلتها بالكامل من لوحة التحكم ← تبويب **الاستبيانات**، لكل استبيان رابط
عام يدخل منه أي زائر مجهول ويعبّيه مباشرة، ودعوات شخصية بالبريد تتابع حالتها
— ويتعايش الاثنان معاً على نفس الاستبيان (شبيه بـGoogle Forms). الخادم:
`api/surveys.php`، والعرض: `survey.html` (يُغذَّى ببيانات الاستبيان من
الخادم، لا أسئلة ثابتة فيه).

### النموذج

استبيان (`surveys`) فيه أسئلة بالترتيب (`survey_questions`) من خمسة أنواع:
اختيار فردي، اختيار متعدد، مقياس رقمي (بحدود وتسميات حرة، يغطي مقياس ١-٥
ومقياس NPS ٠-١٠ بنفس النوع)، نص قصير، ونص طويل — ولأسئلة الاختيار خيارات
(`survey_question_options`) قد يفتح أحدها سؤال متابعة نصياً عند اختياره.
الدعوات (`survey_invitations`) والردود (`survey_submissions` وتفاصيلها في
`survey_answers`) منسوبة لاستبيانها عبر `survey_id`.

### رحلة المدعو والرابط العام

- **دعوة شخصية**: المشرف يرسل دفعة دعوات باسم حملة (حتى ٥٠ بريداً في
  الدفعة، وسقف `INVITE_DAILY_LIMIT` دعوة في اليوم عبر كل الاستبيانات معاً).
  كل مدعو يصله رابط شخصي `/invite/{token}`؛ حالته تقدّمية ولا تتراجع:
  `sent ← opened ← completed`. المدعو يكمل من حيث توقف لو رجع من نفس
  الرابط، ويعدّل إجاباته بعد الإرسال بلا تكرار صفوف.
- **رابط عام**: كل استبيان منشور له رمز رابط عام (`survey.html?s={رمز}`)
  يُفعَّل ويُعطَّل ويُجدَّد من المحرّر — أي زائر يدخله ويعبّي الاستبانة
  مباشرة بلا دعوة ولا بريد. رده مجهول تماماً: يُسجَّل مرة واحدة بلا رجعة
  لتعديله لاحقاً (لا هوية تربطه بردّه السابق).
- استبيان **«تجربة المنصة»** الافتراضي (المبذور تلقائياً بعشرة أسئلة عند
  أول تشغيل) هو الوحيد الذي يمنح **تجربة موسّعة** بلا حساب لمدة
  `BETA_TRIAL_HOURS` ساعة عبر رابط دعوته (`grants_trial`) — بقية
  الاستبيانات لا تمنح هذا الامتياز. بعد أول سؤال حقيقي يطرحه المدعو، تظهر
  في المحادثة بطاقة واحدة تدعوه لإكمال الاستبانة.

### المؤشرات

## أسئلة التحكيم (/judges)

صفحة داخلية تجهّز الفريق لأسئلة لجنة التحكيم. `judges.html` تعرض ما في
`assets/judges-data.js`: مجموعات أسئلة، وبحث عربي وإنجليزي لا يتأثر بالهمزات والتشكيل،
وشاشة «الشائعة» مع أرقام للحفظ، ووضع تدريب يتتبع ما أتقنه كل عضو في متصفحه، ووضع عرض
بخط كبير، وطباعة أو PDF على ورق وصال الرسمي (ترويسة وتذييل يتكرران في كل صفحة، بهامش
`@page` صفر ومساحة محجوزة في جدول، لأن الإزاحة السالبة داخل الهوامش لا يُعتمد عليها).

- **بلا فهرسة:** `noindex` في الصفحة، وترويسة `X-Robots-Tag` في `.htaccess` للصفحة وملفي
  بياناتها، ولا تظهر في أي sitemap. الرابط وحده هو الحماية، فلا يصح وضع سر فيها.
- **ملاحظات الفريق الداخلية لا تدخل Git.** المستودع عام ورابطه في عرض المشروع للجنة، وفي
  الملاحظات كلام صريح (تعارض بين العروض، ومعلومات تحتاج تأكيداً قبل الجلسة). مكانها
  `assets/judges-notes.js`، المستثنى في `.gitignore` ومن حذف `deploy.sh`. يضعه الفريق على
  الخادم بيده في `assets/`، وبغيابه تعمل الصفحة كاملة بلا عناصر «يُؤكَّد من الفريق»، ويسجّل
  المتصفح 404 لذلك الملف وحده في وحدة التحكم، وهي متوقعة.
  لا تضف حقل `v` إلى `judges-data.js`: يفشل `check-judges.js` إن وُجد.
- **سؤال مكرر:** عدّاد على كل سؤال يضغطه الفريق كل مرة تسأله اللجنة. كل ضغطة تزيده واحداً،
  ويرتفع الأكثر تكراراً أول القوائم وأعلى الرئيسية وفي الرأس، ولكل ضغطة «تراجع». العدّادات
  محلية في متصفح كل عضو (`localStorage`)، وتُدمج بين الأجهزة برابط «نسخ رابط للفريق»: من
  يفتحه يرى القائمة ويوافق على دمجها (يؤخذ الأعلى عدداً). ليست مشتركة لحظياً، فذلك يحتاج
  قاعدة بيانات وتسجيل دخول للفريق.
- **الأسلوب:** أجوبة بلهجة سعودية بيضاء وجمل قصيرة، لأنها نص يقوله الفريق لا نص موقع. هذا
  استثناء مقصود من «الفصحى الميسّرة» في قسم الكتابة، وبقية القواعد (لا شرطات، ولا ادعاء
  بلا مرجع) سارية.
- **الإضافة:** سؤال جديد يُضاف في `judges-data.js` بالدالة `Q()`، وكل نص `[عربي، إنجليزي]`،
  وما لم يثبته مرجع يُكتب في الملف الخاص لا في العام.
- **الترتيب:** داخل كل قسم يأتي الأكثر شيوعاً أول. السؤال الشائع في قسمه يحمل `com: 1`،
  والعشرة الأشيع بين الكل تحمل ترتيباً في `hot` من 1 إلى 10 بلا فراغ.

```bash
node tools/check-judges.js    # بيانات الصفحة، وأن الملف العام بلا ملاحظات داخلية
php -S 127.0.0.1:8080 &       # ثم، ويتطلب playwright:
NODE_PATH="$(npm root -g)" node tools/check-judges-ui.js
php tools/check-copy.php      # الشرطات والعبارات الجاهزة، ويفحص judges.html وملف بياناتها
```

## الأمان

- **لا ترفع `api/config.php` إلى Git أبداً.** لو تسرّب مفتاح، جدّده فوراً من
  لوحة المزوّد — الحذف من التاريخ لا يُبطل المفتاح.
- كل الاستعلامات تستخدم عبارات مُعدّة مع `PDO::ATTR_EMULATE_PREPARES => false`.
- كلمات المرور بـ `password_hash()`. الجلسات `HttpOnly` و `SameSite=Lax`
  و `Secure` على HTTPS، مع تجديد المُعرِّف عند الدخول.
- **الخروج التلقائي:** بعد 30 دقيقة دون نشاط للمستفيد، و15 دقيقة لمدير النظام
  والمشرف ومراجع المحتوى، وبعد 24 ساعة و12 ساعة من الدخول مهما كان النشاط
  (`IDLE_MINUTES_*` و`SESSION_MAX_HOURS_*` في `api/config.php`، والمراجع في
  `config.example.php`). النشاط أي حركة: الفأرة، واللمس، ولوحة المفاتيح،
  والكتابة، والاستماع لإجابة تُقرأ صوتياً، وهو مشترك بين التبويبات. قبل الخروج
  بدقيقتين تظهر «هل ما زلت هنا؟» ويمدّدها أي حركة أو زر «أبقني متصلاً» (WCAG
  2.2.1). الخادم هو الحكم (`enforceSessionTimeouts()` في `api/db.php`) بهامش
  دقيقتين فوق الواجهة؛ واستطلاع الإشعارات كل دقيقة يرسل `X-Wesal-Idle: 1` إن لم
  يتحرك المستخدم فلا يُبقي التبويب المفتوح الجلسة حيّة. الواجهة تقرأ المدة من
  `idle_min` في رد الخادم، فلا قيمة مكررة في `index.html`؛ أما بند «الخروج
  التلقائي» في سياسة الخصوصية فيُحدَّث يدوياً إن تغيّرت المدتان.
- **كل خروج** (يدوي أو تلقائي أو أنهاه الخادم) يمسح ما يخص الحساب من المتصفح
  ويعيد تحميل الصفحة، فلا يبقى على الشاشة شيء من بياناته لمن يجلس بعده على
  الجهاز نفسه، ويُخرج التبويبات الأخرى معه. المحادثات المحفوظة لكل حساب على حدة
  (`chats_{id}`)، والقائمة المشتركة القديمة يرثها أول حساب يدخل بعد التحديث.
  الخروج التلقائي لحسابات الفريق يُسجَّل في سجل العمليات.

بعد أي تعديل يمس الجلسة أو تسجيل الدخول:

```bash
php tools/check-session.php    # منطق الخادم وتطابق الواجهة والسياسة مع الإعدادات، آمن على الإنتاج
php -S 127.0.0.1:8080 &        # نسخة محلية بقاعدة تجريبية، ثم:
NODE_PATH="$(npm root -g)" node tools/check-session-ui.js   # سيناريوهات المتصفح (يتطلب playwright)
```
- الصور المرفوعة تُفحص بـ `getimagesizefromstring()` ويُشتقّ امتدادها من النوع
  المُستشعَر لا من اسم الملف، وتنفيذ السكربتات محجوب داخل `uploads/`.
- سياسة `Content-Security-Policy` في `.htaccess` تسمح حالياً بـ `'unsafe-inline'`
  لأن السكربت والأنماط ومعالجات `onclick` مضمّنة في `index.html`. تشديدها
  يتطلّب أولاً إخراجها إلى ملفات منفصلة.

## الوصولية

المنصة موجّهة للأشخاص ذوي الإعاقة، فأي تعديل على الواجهة يجب أن يمرّ على:

- التنقّل بلوحة المفاتيح وحدها من أول عنصر إلى آخره
- قارئ شاشة واحد على الأقل (NVDA أو VoiceOver)
- التكبير حتى ٢٠٠٪ بلا فقدان محتوى
- وضع التباين العالي والوضع الداكن
- «تقليل الحركة» مفعّلاً

### إعدادات الوصول السريعة

زر واحد في الشريط العلوي بجانب زر اللغة، في كل المقاسات، تنسدل تحته لوحة «إعدادات
سريعة»: حجم الخط، والتباين العالي، والوضع الداكن، وتقليل الحركة، ورابط صفحة الإعدادات
الكاملة. قواعدها:

- **لا زر عائم.** كان زر في زاوية الشاشة يفتح اللوحة نفسها، فيغطي المحتوى (ومنه زر
  الإرسال في المحادثة على الجوال)، ويأتي آخر الصفحة لمن يتنقل بلوحة المفاتيح أو قارئ الشاشة.
- اللوحة تلي الزر مباشرة في الصفحة، فأول Tab بعد فتحها يدخلها. وهي مخفية تماماً وهي
  مغلقة (`hidden`)، والزر يعلن حالتها بـ`aria-expanded`. يغلقها Escape (ويعود التركيز
  إلى الزر) أو النقر أو انتقال التركيز خارجها.
- **وضع العرض** يتبع إعداد الجهاز: الوضع الداكن (`prefers-color-scheme`)، وإلا التباين
  العالي (`prefers-contrast`). واختيار الزائر في وصال يتقدّم عليه ويُحفظ، مثل «تقليل الحركة».
- **حجم الخط** يُحفظ في المتصفح، ويُطبَّق مع وضع العرض قبل أول رسم (السكربت الصغير أعلى
  `index.html`)، فلا تومض الألوان ولا يقفز النص.
- على الجوال يظهر زر اللغة مختصراً («EN» أو «ع»)، وللمستخدم المسجّل في الشاشات الأضيق
  من 390 بكسل يظهر رمز الشعار وحده، فيتسع الشريط من عرض 320 بكسل.

### الحركة

حركة الصفحة الرئيسية كلها في `index.html` (الأنماط تحت «حركة الصفحة الرئيسية»،
والمنطق في `heroIntro()`): العنوان يُكتب حرفاً حرفاً بمؤشر، وبقية الواجهة تظهر
عند ٦٠٪ منه، وخطوط الخلفية ترسم نفسها، وحقل السؤال يكتب أمثلة `hero.examples`
دورة واحدة ثم يعود لنصه. قواعدها:

- **«تقليل الحركة»** يتبع إعداد النظام (`prefers-reduced-motion`) تلقائياً، واختيار
  الزائر في وصال (صفحة الإعدادات أو لوحة «إعدادات سريعة») يتقدّم عليه ويُحفظ. معه يظهر كل
  شيء فوراً بلا حركة، وكذلك في معاينة المحرر.
- نص العنوان في الصفحة لا يُمسّ أثناء الكتابة (يُكشف بـ`clip-path` فقط)، فقارئ
  الشاشة ومحرك البحث يقرآنه كاملاً، والحروف العربية تبقى متصلة.
- لا شيء يزحزح التخطيط، وكل حركة تنتهي وحدها خلال ثوانٍ، والعنصر الذي يصله
  التركيز بلوحة المفاتيح يظهر فوراً دون انتظار حركته.
- لإيقاف أمثلة حقل السؤال: احذفها أو أخفها كلها من محرر صفحة الهبوط.

### نقاط الياء في الحقول

خط ثمانية يصرّح بنزول 0.25em تحت السطر، بينما نقطتا الياء وذيول الحروف العربية
تنزل حتى 0.54em تقريباً، والمتصفح يقصّ نص الحقل عند حدود سطره فتظهر «في» كأنها
«فى». لذلك كل حقل بسطر واحد (وقائمة اختيار) يأخذ `line-height:2` مع حشوة رأسية
أقل بالفرق (`calc(… - .375em)`) فلا يتغيّر ارتفاعه، ونصه البديل `overflow:visible`
لأن كروم يفرض على صندوقه سطراً عادياً. أي حقل جديد بغير `.form-input` يحتاج المثل.

### دورة السؤال في المحادثة

رد واحد قيد الوصول في كل مرة، من إرسال السؤال حتى اكتمال رده بأي مسار (البث من
`chat-stream.php` أو البديل `chat.php`). طوال ذلك يصير زر الإرسال زر إيقاف، وEsc في
خانة السؤال يوقف الرد أو قراءته الصوتية، وEnter يرسل. كل سؤال يحمل رقم دورة
(`data-turn`) على فقاعته وعلى كل رد له:

- **تعديل آخر سؤال في مكانه:** القلم يحوّل فقاعة السؤال إلى خانة تعديل تحتها ✓ و✗،
  والرد الجاري يكمل أثناء التعديل.
  - ✗ أو Esc يعيد السؤال كما كان ويبقى رده.
  - ✓ أو Enter يضع النص الجديد مكان السؤال برقم دورة جديد، ويوقف الرد الجاري، ويزيل
    ردود النص القديم ويسحبها من سياق النموذج (`hist`) ومن المحفوظات، ثم يجيب عن
    النص الجديد. نص لم يتغير كالإلغاء.
  - ✓ يوقف أيضاً قراءة الرد القديم بالصوت. والنص المعدّل مكتوب لا مملى، فرده لا
    يُقرأ إلا بالقراءة التلقائية، ولو أُرسل السؤال الأصلي بالصوت.
  - الرصيد كسؤال جديد، والقديم لا يُسترد لأن الخادم خصمه حين بدأ الرد.
- **إعادة التوليد** تعرف سؤالها برقم الدورة لا بموضعها في السجل.
- أي رد يصل لرقم دورة قديم يُهمل: لا يظهر ولا يُحفظ.
- `chat-stream.php` و`chat.php` يحرران قفل الجلسة بعد خصم الرصيد (`session_write_close()`)،
  فلا ينتظر أي طلب آخر من المتصفح نفسه اكتمال الرد، ومنه طلب البديل إن انقطع البث.
- لا عنصر ثابت يغطي زر الإرسال والإيقاف، وأي عنصر ثابت جديد قرب خانة السؤال يحتاج
  مساحة محجوزة له (يفحصه `check-chat-ui.js` على خمسة مقاسات).

بعد أي تعديل على المحادثة:

```bash
php -S 127.0.0.1:8080 &
NODE_PATH="$(npm root -g)" node tools/check-chat-ui.js   # لا يحتاج قاعدة بيانات ولا مفتاح نموذج
php tools/check-stream.php    # محرّك البث من المزوّد، ويفشل إن عاد رد المزوّد لا يصل البث
```

## كتابة النصوص الظاهرة للمستخدم

كل نص يراه الزائر أو المستخدم (الصفحات، والتنبيهات، ورسائل الأخطاء، والبريد،
وردود المساعد الجاهزة) يلتزم بهذه القواعد:

- **لا شرطة طويلة (—) ولا قصيرة (–) بين الكلام.** مكانها الفاصلة أو النقطة،
  والنقطتان قبل التفصيل، والقوسان للاعتراض، و«إلى» في المدى الزمني. عنوان
  تبويب المتصفح وحده يفصل بـ «|»، والخانة الفارغة في الجداول تُعرض «-».
- **الفصحى الميسّرة** في الموقع والرسائل والبريد والسياسات. ردود المساعد
  وحدها باللهجة السعودية البيضاء كما في تعليماته (`chatSystemPrompt()`).
- **جملة قصيرة ومعلومة محددة** بدل الصفات العامة. نتجنب «تجربة فريدة» و«قوة
  الذكاء الاصطناعي» و«رحلتك المعرفية» و«في صميم» و«ليس مجرد»، ونقلل «فعلاً»
  و«بالكامل» و«تماماً».
- **لا ادّعاء بلا دليل:** لا رقم ولا «الأول» ولا «آلاف» ما لم نستطع إثباته،
  ولا نَعِد بما لا تفعله المنصة (المحادثات المحفوظة مثلاً تبقى في المتصفح).
- **المصطلحات:** «الأشخاص ذوو الإعاقة»، و«بطاقة إثبات الإعاقة»، وأسماء
  الأدوار كما في `roleName()`. «وصال» مذكّر حين نقصد المساعد (يجيبك وصال)،
  ومؤنث حين تسبقه «منصة» (منصة وصال تتيح).

قبل أي دمج يغيّر نصاً ظاهراً:

```bash
php tools/check-copy.php      # يفشل إن وُجدت شرطة في نص ظاهر
php tools/check-landing.php   # يتحقق أن سجل صفحة الهبوط يطابق index.html
```

الفحص لا يرى ما يُكتب من محرر صفحة الهبوط ويُحفظ في قاعدة البيانات، فهذه
القواعد نفسها تنطبق على من يحرر المحتوى من لوحة التحكم.
